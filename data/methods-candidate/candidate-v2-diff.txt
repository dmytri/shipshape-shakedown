+### Methods
+
+A method is a named composition of `## Commands` values that a role runs as ONE invocation at a step these Articles name, so a step that would spend a round trip per command spends one for all of them. The commands themselves are already specified in `RIGGING.md` and run verbatim; a method carries that same contract one level up, so WHICH commands a step entails, and whether they arrive together, is fixed at fitting out rather than inferred at each point of use. +A command set is eligible to be a method only where no part depends on another part's output, and no part is chosen from another part's result. A set whose next command the step picks from the last command's output is reactive: it is not a method, and composing it would make the role choose blind. A method never adds an act. It composes the commands its step already runs, so a project that derives no method loses no obligation, and a project that derives one takes on no new work.

+A method value is one Yoink plan, in backticks as every command value is. A shell sequence carries the parts but not their statuses, and a shell chain joined by `&&` is worse, because it stops at the first non-zero exit and hides every part behind it.
